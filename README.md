# Git & GitHub Guidelines

How the Synapse team branches, commits, reviews, and ships. Every Synapse repo follows these rules.

The full guide is [`index.html`](index.html). It covers the branch model, naming, commit format, PR and review rules, branch protection, CI/CD, releases, hotfixes, and a setup checklist for each repo.

## View the guide

- **Locally:** clone this repo and open `index.html` in a browser.
- **On GitHub Pages:** go to Settings → Pages, set Source to *Deploy from a branch*, and choose `main` / `(root)`. The guide is then served at `https://<owner>.github.io/git-github-guidelines/`.

## Summary

| Topic | Rule |
|---|---|
| Branches | `main` = production, `develop` = staging. Work happens on short-lived `type/short-desc` branches. |
| Direct pushes | Blocked on `main` and `develop` for everyone, admins included. Every change goes through a PR. |
| Merging | CI must pass, conversations must be resolved, and a code owner must approve. `develop` needs 1 approval and `main` needs 2. |
| Merge method | Merge commits only. Tidy your branch history before you request review. |
| Commits | [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/), enforced by commitlint locally and in CI. |
| Releases | SemVer tags, the changelog, and GitHub Releases are generated by release-please. Nobody tags by hand. |
| Hotfixes | Branch from `main`, open a PR into `main`, then back-merge into `develop` the same day. |
| Secrets | Secret scanning and push protection are on. If a secret leaks, rotate it first and clean history second. |

### Branch names

```
feature/jwks-rotation      bugfix/null-token-refresh   hotfix/login-500
refactor/split-token-svc   chore/node-24-upgrade       docs/auth-flow-diagram
```

### Commit messages

```
<type>(<scope>): <subject>

feat(auth): add JWKS endpoint with key rotation      → minor
fix(gateway): return 401 when token kid is unknown   → patch
feat(api)!: drop v1 session endpoints                → major
```

Types: `feat` `fix` `perf` `refactor` `test` `docs` `build` `ci` `chore` `style` `revert`

### Daily workflow

```bash
git switch develop && git pull --ff-only      # or: git checkout develop
git switch -c feature/jwks-rotation           # or: git checkout -b feature/jwks-rotation
# ...commit...
git fetch origin && git rebase -i origin/develop   # only before review starts
git push -u origin feature/jwks-rotation --force-with-lease
gh pr create --base develop --draft --fill
```

## Proposing a change

These guidelines follow their own rules. To change them:

1. Branch from `main`, for example `docs/raise-pr-size-limit`.
2. Edit `index.html`, and this README if the summary changes.
3. Open a PR with a Conventional title, for example `docs: raise PR size limit to 500 lines`.
4. Merge after approval from 2 leads.
